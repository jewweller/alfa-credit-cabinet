# Frontend — кредитный кабинет предпринимателя

React 19 + Vite + TypeScript, TanStack Query, react-router. Данные — через API `/api/v1`
(контракт `docs/api/openapi.json`); пока бэк не готов, ответы дают MSW-моки.

## Запуск

```bash
cd frontend
npm ci
npm run dev        # http://localhost:5173
```

Node 20+ (`.nvmrc`). Без бэка всё работает на моках: `VITE_USE_MOCKS=true` в `.env.development`.
Когда бэк поднят на `:8000`, поставьте `VITE_USE_MOCKS=false` — Vite проксирует `/api` туда.

## Запуск в Docker

Из корня репозитория: `cp .env.example .env && docker compose up --build`, затем
http://localhost:8080. Сервис `frontend` собирает Vite и отдаёт статику через nginx, `/api`
проксируется в сервис `api`. По умолчанию `VITE_USE_MOCKS=true`: экраны работают на моках
в браузере, потому что бэк пока не закрывает подписание и кабинет банка. `VITE_USE_MOCKS=false`
в `.env` и `docker compose up --build` — все запросы идут в настоящий API.

## Моки и сценарии

- Вход — демо-учётками из плана (раздел 14), пароль у всех `Demo2026!`. На экране входа они
  перечислены, нажатие подставляет учётку (спрятать: `VITE_DEMO_MODE=false`). Заявки в исходных
  данных есть только у `bakery@demo.local`; Ковалёв, СтройРесурс и Мельникова начинают с нуля:
  подбор (C3) → мастер (C4) → отправка → карточка (C5) → подписание (C6, код на экране,
  симуляция ПЭП) → выдача (C7, график платежей). Сотрудники банка (`underwriter@demo.local`)
  попадают в очередь `/bank` (B2) → карточка заявки (B3) с решением специалиста (B4).
  Лента на отдельном экране (C8) — следующий шаг.
- Конвейер — как в плане (раздел 7): скоринг F1–F6 (`src/mocks/scoring.ts`) по ответам ЕГРЮЛ/ЕГРИП,
  ФНС и БКИ (`src/mocks/sources.ts`), затем правила R1–R10 по порядку (`src/mocks/decision.ts`).
  Пекарня — одобрение (R9), Ковалёв — другие условия (24 мес, R10), СтройРесурс — отказ
  (R1, компания ликвидирована), Мельникова — запрос декларации (R4), после загрузки — ручное
  рассмотрение: решает специалист в кабинете банка. Клиент и специалист работают в одной
  вкладке — выйти и войти другой учёткой (состояние моков живёт в `sessionStorage` вкладки).
- `?scenario=empty` — у клиента нет заявок; `?scenario=error` — список заявок отвечает 500;
  `?scenario=registry_down` — реестр ЕГРЮЛ/ЕГРИП не отвечает (шаг «Компания» в мастере).
- Моки помнят действия: загрузка файла, принятие оффера, повторная отправка. «Конвейер» сам
  двигает статусы раз в 2,5 с. Состояние живёт в `sessionStorage` вкладки: F5 его сохраняет,
  новая вкладка начинает с исходных данных, `?reset=1` сбрасывает текущую.
- Заявки ООО «Пекарня Север» (`src/mocks/data.ts`) покрывают все сценарии карточки C5:
  №1042 — нужны документы (R4), №1055 — другие условия (R10, 18 мес), №1051 — одобрится
  через 10 с, №0950 — отказ специалиста после R5, №0987 — выдан, №1048 — черновик.
- В очереди банка ещё три компании без демо-входа (учётки `vektor@`, `mirage@`, `sboy@` — как в
  `seed/users.json` бэка): ООО «Вектор» — отказ (R2, просрочка 120 дней),
  ООО «Мираж» — ждёт специалиста (R7, грейд D), ООО «Сбой-Тест» — ждёт специалиста (R3, БКИ
  не ответило).

## Типы из контракта

```bash
npm run api:types  # docs/api/openapi.json → src/api/schema.ts
```

`src/api/schema.ts` сгенерирован, руками не правится. Генератор (openapi-typescript) требует
TypeScript 5, поэтому запускается через `npx` в изоляции и не ставится в зависимости.

## Структура

| Папка | Что внутри |
|---|---|
| `src/api/` | клиент API, сгенерированные и производные типы |
| `src/features/` | данные и логика экранов (хуки TanStack Query), без стилей |
| `src/pages/auth/` | вход (C1, он же B1) |
| `src/pages/client/` | экраны клиента C2–C7, заглушка ленты C8 |
| `src/pages/bank/` | экраны банка: B2 очередь, B3 карточка заявки с решением B4 |
| `src/ui/` | компоненты на дизайн-токенах |
| `src/theme/` | `tokens.css` — все цвета, отступы, тени; темы «жемчуг» и «графит» |
| `src/i18n/ru.ts` | все тексты, включая словарь «статус → блок, этап, кнопка» |
| `src/mocks/` | MSW: данные, состояние, обработчики, расчёт графика |

Общие компоненты — в `ui/`, страницы и `features/` собираются из них. Блоки, нужные одному
экрану (таблица очереди, скоринг, форма решения), держат свой `*.module.css` рядом с кодом —
только на токенах. Оформление меняется в `src/theme/tokens.css`.

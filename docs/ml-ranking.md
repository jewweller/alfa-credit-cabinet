# ML-ранжирование: что модель получает и что возвращает

Версия от 24.10.2026. Схемы — `backend/app/schemas/ml.py`, примеры — `docs/ml/*.json` (их проверяет `backend/tests/unit/test_feed.py`).

## Роль модели

Модель **только меняет порядок** кандидатов, которых уже отобрал бэкенд. Она не добавляет и не убирает кандидатов, не меняет суммы, ставки и платежи. Кредитное решение принимают правила R1–R10 и специалист банка — ML-скоринга в проекте нет (план, раздел 3: «Won’t»).

Две задачи:

| Задача | Экран | Кандидаты | Без модели |
| --- | --- | --- | --- |
| **Лента** — главная | C2, C8 | 5–15 новостей из `seed/news.json`, прошедших фильтры | формула весов плана (`backend/app/domain/feed_ranking.py`) |
| **Подбор продукта** | C3 | 1–3 продукта из `seed/products.json` | порядок бэкенда: сначала подходящие без изменений |

На подборе ранжировать почти нечего: два кандидата бывают только у цели «кассовый разрыв». Основная ценность ML — в ленте.

## Данные

Только синтетические, всё в репозитории. Доступа к данным банка нет и не будет (условия кейса).

| Что | Файл |
| --- | --- |
| Новости с тегами | `seed/news.json` (28 шт.) |
| Продукты | `seed/products.json` |
| Компании | `seed/companies.json` |
| Выручка из ФНС | `mocks/fixtures/fns_tb.json`, поле `response.revenue` |

**БКИ модели не передаём.** Согласие на запрос в БКИ клиент даёт для решения по своей заявке, а не для подбора продуктов и новостей. ИНН и название компании модели тоже не нужны.

## Как вызывается

Предложение по умолчанию (согласовать с backend): пакет `ml` экспортирует две функции **JSON → JSON**:

```python
def rank_feed(payload: dict) -> dict: ...      # FeedRankRequest → FeedRankResponse
def rank_products(payload: dict) -> dict: ...  # ProductRankRequest → ProductRankResponse
```

- бэкенд вызывает их в своём процессе, таймаут 1 с;
- модель не ходит в сеть и БД, веса — файл в репозитории, лицензия открытая;
- включается переменной `ML_RANKING_ENABLED=true`; по умолчанию выключено.

## Вход: лента (`FeedRankRequest`)

Пример — `docs/ml/feed-rank.request.json` (Пекарня, заявка одобрена).

| Поле | Что это |
| --- | --- |
| `now` | текущее время — для свежести |
| `profile.kind`, `okved_main`, `region`, `segment`, `registered_at` | профиль компании |
| `profile.revenue` | выручка по годам из ФНС; может быть `{}` |
| `profile.applications[]` | заявки клиента: `status`, `product_code`, `purpose` |
| `candidates[]` | новость целиком (`id`, `title`, `body`, `topic`, `tags`, `published_at`) плюс `rule_score` — вес по формуле и `matched` — совпавшие теги |

Кандидаты уже прошли фильтры правил: отраслевые заметки — только своей отрасли, подсказки — только к текущему статусу заявки.

## Выход: лента (`FeedRankResponse`)

```json
{
  "model_version": "feed-ranker-0.1.0",
  "ranking": [
    { "id": "9e0a1b2c-0000-4000-8000-000000000007", "score": 1.0,
      "reasons": [{ "code": "okved", "text": "Ваш ОКВЭД 10.71 — производство хлеба и мучных изделий" }] },
    { "id": "9e0a1b2c-0000-4000-8000-000000000006", "score": 0.86, "reasons": [] }
  ]
}
```

- в `ranking` **все** кандидаты, каждый ровно один раз, лучший первым;
- `score` — от 0 до 1;
- `reasons` — до двух строк «Почему вы это видите», `code` из списка `okved | segment | product | status | general`, `text` до 120 символов. Пусто — бэкенд покажет причины по правилам.

## Вход и выход: подбор продукта

Примеры — `docs/ml/product-rank.request.json` и `.response.json`.

- вход: `request` (`purpose`, `amount`, `term_months`), `profile` (как в ленте), `candidates[]` — элементы ответа `POST /products/recommend`;
- выход: `ranking[]` из `product_id`, `score` (0…1), `reasons` (до двух строк до 120 символов, в интерфейсе пока не показаны).

## Когда ответ отбрасывается

Бэкенд оставляет порядок по правилам и пишет предупреждение в лог, если:

- функция бросила исключение или не уложилась в 1 с;
- ответ не проходит схему (`score` вне 0…1, длинная причина, повтор `id`);
- в `ranking` не те кандидаты (`is_permutation` вернул `false`).

Клиент разницы не заметит. В ответе `GET /feed` поле `ranking.method` покажет `rules` вместо `ml`.

## Как понять, что модель лучше правил

Метрику и разметку выбирает ML-команда. Минимум для README: на каком наборе сравнивали с `rule_score`, какая метрика (например, NDCG@5), и что модель не нарушает фильтры правил.
